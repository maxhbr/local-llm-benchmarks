# llama-benchy factor: rtx5090 vs gfx1151

Performance factor between rtx5090 and gfx1151 from matching `llama-benchy.md` runs. For every model benchmarked on **both** GPUs (21 models), the factor is **rtx5090 is N× faster than gfx1151**:

- throughput metrics (t/s …): `rtx5090 / gfx1151` (higher is better)
- latency metrics (ttfr / est_ppt / e2e_ttft, in ms): `gfx1151 / rtx5090` (lower latency is better, inverted so `> 1` means rtx5090 is faster)

**`> 1.0` ⇒ rtx5090 wins · `< 1.0` ⇒ gfx1151 wins.** The *overall* column is the geometric mean of every d0 (base-depth) throughput and inverted-latency factor (equal weight per cell in log-space).

### Caveats

- Extreme factors (very large, or near 0) are read straight from the source `llama-benchy.md` files. They usually mean one GPU's run broke at that depth/concurrency (e.g. an absurd t/s from a measurement error, or a genuine collapse such as rtx5090 stalling at c4). They are kept as-is rather than clamped, so the table stays faithful to the runs.
- The *overall* geo-mean only uses base-depth (d0) cells, so the deep-context (d8192/d16384) blow-ups do not pull it around, but a single catastrophic d0 cell can still move it noticeably.
- Cells shown as `-` mean the metric was empty for that test on one or both GPUs (e.g. `peak t/s` is only populated for `tg` rows, latency cols only for `pp` rows).
